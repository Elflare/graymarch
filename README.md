# 灰境战术 · Graymarch

一个无限地图探索、生存补给与三步战斗规划的单人游戏。人和 AI 操作同一页面、同一局；AI 通过本机 HTTP JSON API 玩，不截图、不模拟点击。

## 启动

需要 Python 3.14+、[uv](https://docs.astral.sh/uv/) 与支持 ES modules / WebSocket 的现代浏览器。在本目录执行：

```sh
uv run graymarch
```

可用参数：`--no-browser`、`--port 8765`、`--config config.example.toml`。默认地址严格为 `http://127.0.0.1:8765`。自动打开失败时在本机打开 `.runtime/open-game.html` 完成配对（五分钟内有效），不要分享该凭据文件。Agent token 保存在 `.runtime/agent-token`，详见操作指南。

首次运行由 uv 安装依赖。启动器提供本机服务并打开游戏页。保持终端与主游戏页面开启；关闭终端会停止 API，关闭/刷新页面会失去当前未保存进度。浏览器后台冻结、电脑睡眠不保证继续运行。不应直接双击 HTML，也不要把服务暴露到公网。

本版采用 Python 薄桥 + JavaScript 唯一规则核心：外部 agent → HTTP JSON → Python → WebSocket → 原游戏页面。Python 负责认证、路由、连接和文件存档，不计算战斗结果；UI 和 API 均提交语义命令，动画不是游戏规则的时钟。

## 人怎么玩

游戏启动默认由 Agent 控制。要亲自操作，先点击“暂停 · 人工接管”；Agent 模式点击读档会提示“请人工接管后读档”。手动读档期间会暂停，成功后自动交回 Agent，失败则保留原旅程并维持人工模式。同一页面重连保留当前控制模式。

1. 在世界地图用方向键或点击相邻格四向移动。悬停地形、行动与状态查看说明；“探索总览”只展示已发现区域。
2. 在荒原、草原、森林、沼泽采集，点击行囊食物进食；营火可休息或料理。战斗中不能进食。
3. 遭遇敌人后先看敌方已锁定的三步，再安排自己的三槽计划。点击已选槽撤回，未填槽会等待；执行一次结算最多三步。
4. 升级后选择一个技能、被动或装备。处理所有待选奖励后才能继续探索。
5. 击败不同地点的精英获得三枚塔印，再循导航挑战赤塔领主。通关可继续探索，也可开启保留永久解锁的新旅程。
6. 结束游玩前手动保存当前旅程。局外成长（通关次数、最佳评价、累计采集与永久解锁）自动保存，打开游戏自动恢复。

## AI 怎么玩

先阅读本 README 的规则，再读 [Agent 操作指南](docs/agent-guide.md)。首选 compact 观察 → 判断阶段/选项 → 必要时预演 → 提交一个带版本的命令 → 使用响应中的新观察继续。API 只给当前决策所需信息，不在每个响应重复规则教程。

- `GET /api/v1/status`：连接、控制模式与当前身份
- `GET /api/v1/observation`：默认 compact 当前决策帧；sync 用于有状态缓存客户端
- `GET /api/v1/information`：按需完整玩家可见快照，默认不限频
- `GET /api/v1/catalog`、`GET /api/v1/map`：公开定义和已发现地图
- `POST /api/v1/preview`：只读预演
- `POST /api/v1/actions`：提交语义动作
- `GET /api/v1/commands/{commandId}`：确认命令结果，避免超时后重复操作

常用操作集中在 [tools/agent/](tools/agent/)，仅用 Python 标准库。在项目根目录使用 `./gm`，入口会通过 uv 运行客户端：

```sh
./gm status
./gm observe
./gm move west
./gm move east 5
./gm preview basic_guard charge basic_attack
./gm fight basic_guard charge basic_attack
./gm choose OPTION_ID
```

`./gm --help` 查看全部命令。`harvest`、`eat roots`、`camp`、`cancel`、`plan` 封装对应操作；`wait` 表示三槽计划中的空槽。技能和选项必须使用当前观察提供的 ID；上述蓄力示例要求已经学会该技能。所有动作仍由调用者决定，工具只自动填入版本、身份、战斗批次及 decisionId。

`./gm move east 5` 一次调用向东连续移动最多 5 格，内部逐格提交并复用响应；遇战斗、事件、升级选择、死亡、障碍、异常移位或请求未确认时停止。只输出起点到终点的一份变动简报，附 `movement.requested`、`movement.moved` 和 `movement.stop`；经过的营火、聚落、遗迹以 `movement.sites` 简记，不输出逐格回执。不会自动处理沿途选择或采集，步数省略时仍走一格。`--raw` 返回最后一条回执及移动统计。

动作默认输出紧凑 JSON：`status`、`revision`、`changes`，变化使用结算后的新值。角色数值、背包、构筑和状态只列变动项；移动后附有变化的周边地形、通行费用、当前采集/营火机会和导航。开战或下一批计划带新的敌人数值与锁定意图；事件/升级带当前选项；新学内容带新增定义，避免为了下一步决策再查一次。稳定定义、零库存、旧战报和逐步事件不重复输出。

采集后立即遇袭也会报告到账后的库存，例如 `changes.player.inventory.berries = 2` 表示当前两份黑莓。原始成功回执的 `inventoryChanges` 只含实际变化物品的最终数量，重复收到同一回执不应累加。

`./gm observe` 提供当前角色与决策；可加 `--scope scene` 只看场景、`--scope build` 看构筑效果、`--scope inventory` 看非零库存、`--scope player` 看角色、`--scope map` 看附近已发现地图。全局已发现地图用 `./gm map`，定义用 `./gm catalog`；`./gm information --scope scene` 也只展示场景，省略地图正文。地图默认用紧凑列表示坐标、地形、费用和状态标记，保留分页信息；查询不会重复携带身份字符串、协议版本或旧战报。`player` / `inventory` / 局部 `map` 查询使用主动 information，遵守宿主主动信息限频。加 `--raw` 获取未经精简的完整 API 响应。公共参数 `--url`、`--token-file`、`--raw`、`--wait-timeout` 可以放在子命令前后。

启动完成后默认启用 Agent 控制；先确认 status 的 connected、ready 和 controlMode。人工接管后等待玩家再次交回控制权。独立动作命令先读一次 compact；pending 或提交超时后只查询原命令回执，默认最多等待 30 秒。动画阻塞时等待后确认决策未变化才重试；状态变化或结果未知时停止并输出恢复信息。退出码 0 表示成功，1 表示错误/拒绝，2 表示 pending/unknown；未确认时用 `./gm command COMMAND_ID` 查询，别盲目重做。

Python 脚本可用 `from tools.agent import GraymarchClient`，调用 `move/preview/fight/choose` 等方法，并复用动作返回的新观察；底层 `observe/information/act/command` 仍可用。`act()` 只提交一次，`execute()` 和常用动作方法会等待本次回执并处理动画阻塞。原 [examples/agent_client.py](examples/agent_client.py) 保留为兼容入口，仍输出完整 JSON。

准确请求字段、身份保护、控制权和恢复步骤见操作指南。宿主配置 `full_info.min_turn_interval = 0` 表示主动完整信息查询不限制回合间隔；正整数才启用限频。这不是按秒限流。

## 玩法数据与配置

服务启动配置继续使用 `config.example.toml`（通过 `--config` 指定）；玩法数据统一位于 [`web/data/`](web/data/)，使用标准 JSON：

| 文件 | 内容 |
|---|---|
| `classes.json` | 职业基础属性、初始构筑、物品与介绍 |
| `skills.json`、`passives.json`、`equipment.json` | 各级参数、耗能、冷却、解锁等级与说明模板 |
| `enemies.json` | 敌人属性、行为参数、行动名称、图鉴说明 |
| `foods.json`、`buffs.json` | 食物恢复量、概率、旅途效果及持续时间 |
| `events.json` | 区域/普通事件、选项收益、营火配方 |
| `world.json` | 地形、生态、生成阈值、采集、掉落、距离强化与导航参数 |
| `rules.json` | 初始设置、战斗/成长参数、评价、永久解锁、规则说明与玩法消息 |

修改数据后刷新页面生效；刷新前保存旅程。资源只在启动时加载，游戏中不热更新。JSON 不支持注释和尾随逗号。缺失文件、无效字段、错误 ID 引用或不完整等级表会阻止启动，页面显示文件及字段位置并提供重试。

技能等内容的 `levels` 数组按等级 1 开始排列，必须完整覆盖 `max`。例如修改 `skills.json` 中重斩第一级的 `damageBonus`，实际伤害与说明模板中的 `{damageBonus}` 会一起更新；不要把数值直接填进模板。可选效果说明放在 `details`，`when` 指向对应参数，参数启用时才显示该片段。敌人图鉴、食物和旅途效果也从对应参数生成说明。ID 和已有机制名称保持稳定；新增机制需要实现 JS 执行函数。事件效果仅支持已有的物品、生命、饥饿、经验、旅途效果、战斗及固定随机来源。

[`GameResources`](web/src/content/resources.js) 统一校验并保存只读资源。浏览器入口用 `fetch` 加载；Node 测试用文件读取加载，随后通过 `createGame({resources, ...options})` 注入同一类资源。游戏核心保持同步，不读文件、不发网络请求。资源不写入存档，当前 `schemaVersion: 1` 存档继续可读；已保存的敌人、锁定意图和待选决策保留原快照，后续生成内容使用本次启动加载的数据。新存档会固化当前事件与营火选项的收益，内部事件效果不出现在 Agent 观察中；迁移前的事件存档没有效果描述，仍按原有来源坐标、使用当前资源重建。

## 通用规则

### 目标与地图生态

地图按坐标生成，可持续向外探索。每次移动一格，只能上下左右；山地与深水不可通行。进入视野的地块永久记忆，发现与亲自到访是两件事；未发现区域不提供给 agent。角色周围曼哈顿距离 2 格内会被揭示。

大型生态区域决定地形聚集与常见敌人：风歌平原较安全、易补给；黑木密林富食物但多兽类；灰苔湿地多沼泽与水道；裂脊高地多山岩与重甲；灰烬边境多亡灵和秘法敌人；赤塔疆域更加危险。越远离起点，可能出现更高阶和强化敌人。界面所列敌情比例是地图分布提示，不等于每走一格再随机掷一次遭遇。

| 地形 | 基础移动饥饿 | 机会/限制 |
|---|---:|---|
| 旧王道、风草原 | 1 | 道路不能采集；草原适合补给 |
| 灰境荒原 | 2 | 可采集，收益较低 |
| 黑木林 | 3 | 可采集，多食物与伏击 |
| 灰苔沼泽 | 4 | 可采集，负面状态风险较高 |
| 聚落 | 1 | 每处首次到达 +5 HP、+20 饥饿、甜根×1 |
| 营火 | 1 | 每处可休息或料理一次；只打开后离开不消耗 |
| 遗迹 | 2 | 每处首次到达补满能量并给经验 |
| 事件 | 2 | 每处首次触发；必须处理当前选项 |
| 普通敌人 / 精英 | 2 / 3 | 未清理地点触发战斗；精英给塔印，最多三枚 |
| 赤塔 | 2 | 三枚塔印后挑战最终 Boss |
| 山地 / 深水 | 不可走 | 绕行 |

移动实际费用 = max(1, 地形基础费用 − 寻路者等级 + 旅途效果修正)。已经清理的敌人地点不会反复产出塔印。导航是方向和粗略距离，不能推导 API 没公开的精确位置。

### 生存、采集与世界时间

HP、能量、饥饿均有上限。移动、采集、实际使用营火与真实战斗中的完整回合会推进世界时间；旅途效果按世界时间减少剩余回合。进食本身不推进世界时间，但属于一次真实决策。相同 ID 的旅途效果刷新/替换，不无限叠层。

饥饿归零后，每次世界回合结算扣除当前最大生命的 10%（向上取整，例如最大生命 18 时扣 2）。战斗三步中的每个完整小回合分别结算；查询、预演和计划编辑不扣血。生命归零立即结束本局，探索中不会被救回起点。比例来自 `web/data/world.json` 的 `starvationHpRatio`。

每格只可采集一次，失败也消耗该机会。采集分别判定收获、负面状态和伏击，收获成功仍可能遇袭。基础数据如下，实际费用与概率请读当前格：

| 地形 | 基础费用 | 收获率 | 伏击率 | 负面状态率 |
|---|---:|---:|---:|---:|
| 荒原 | 4 | 38% | 8% | 8% |
| 草原 | 3 | 52% | 7% | 6% |
| 森林 | 5 | 60% | 16% | 12% |
| 沼泽 | 6 | 54% | 14% | 22% |

采集费用受旅途效果增减（最低 2）；本版修正旧版减耗不生效的问题。采集者每级增加 7 个百分点收获率（上限 78%），前两级各降低 1 个百分点伏击/负面概率（分别最低 4%/3%）；2 级开始有双份概率。森林可能造成格挡减弱或额外消耗；沼泽可能攻击减弱或额外消耗。食物/料理完整表见 [内容参考](docs/reference.md)。先补给再进入困难战斗，战斗中无法翻行囊。

### 三步战斗的顺序

敌人先锁定未来三步，玩家后规划。普通攻击 `basic_attack` 和基础格挡 `basic_guard` 永远可用；技能效果、能耗和冷却见当前技能描述。冷却按每步推进，跨计划批次延续，新战斗重置。计划固定为三槽，`null` 是等待。封印槽必须为空。

每一小步依次执行：

1. 玩家行动：扣本步技能能量，结算伤害/治疗/状态/战术效果。
2. 玩家若已击杀敌人，立刻结束战斗，不再挨该步攻击。
3. 敌人执行原本已锁定的行动；打断可取消本步，时滞可推迟到下一组，逆序可交换后两步。不能因敌人中途掉到另一个血量区间就擅自重算当前组。
4. 若未结束战斗，结算流血、灼烧、中毒，递减战斗状态时间；恢复 1 能量（不超过上限），推进战斗回合和真实世界时间，检查胜负。

三步都结束后清空计划，锁定下一组三步。能量逐步检查，并非要求三步费用总和小于当前能量；中途回能、吸能会影响后续。某一步能量不足时该技能失败，敌人仍会行动，不会自动换成普通攻击。预演是规划工具，未知意图之后不能声称精确预测。多次攻击、反伤、持续伤害都可能提前结束战斗。

### 伤害、格挡与状态

- 普通直接攻击先减护甲，基础伤害最低 1，再加符合条件的构筑加成，最后消耗敌人格挡，余量扣 HP。无视护甲不等于无视格挡。
- 格挡累积并在受伤时消耗，不在每小步自动清空；下一场战斗重置。基础格挡为 3 + 塔盾等级 + 旅途格挡修正。具体技能的格挡效果以该技能定义为准。
- “第三击”等加成针对规则中的伤害调用，不是“三步中固定第三槽”。旋风的各次攻击独立结算护甲、格挡与攻击触发条件。
- 精准格挡要求格挡值恰好等于减伤后的攻击、且完全挡住；格挡过量不是精准格挡。反击要求完全挡住并实际吸收伤害，荆棘在格挡吸收伤害时触发。
- 流血/灼烧与玩家中毒在回合末扣 HP。持续时间包含施加当步的回合末结算/递减；“持续 2 回合”不是再额外等两组三步。破甲、霜缚、反击架势等同样按小步计时。
- 护甲降低到 0 为止；石像攻击后短暂破绽再降 2 护甲。玩家的格挡不自动阻止毒素或吸能附加效果，除非当前实现明确标注。
- 蓄力加成消耗于下一次伤害调用；连携斩检查上一小步是否防御类动作。等待会打断该连携条件。

具体技能每级数值、能耗、解锁门槛、被动与装备见 [内容参考](docs/reference.md)，运行时 catalog/当前帧提供实际有效定义。

### 成长、评价与永久解锁

每级升级所需经验为 `8 + level×4 + floor(level^1.25)`。战斗和部分地点/事件提供经验；经验跨过多级就依次选多轮奖励。战斗胜利不保证每次升级。

升级每轮从当前可用池提供最多三个不同选项，选一项：主动技能、被动规则或装备。已有内容通常提升一级；后期新内容可直接追赶到更高等级。选项略偏向已有构筑和升级项，稀有战术权重较低；最高等级或未满足解锁条件的内容不入池。目标等级由引擎决定，agent 不得传入任意等级。

战术评价：无伤且不超过 6 小步为 S；受伤不超过 3 且不超过 9 小步为 A；受伤不超过 7 为 B；其余 C。额外战斗经验分别为基础经验的 20%/10%/5%/0%，向上取整。精确终结还可因恰好击杀另加经验。以战报实际统计为准。

| 职业 | 基础 HP / 攻击 / 能量上限 / 饥饿上限 | 初始构筑 | 永久解锁条件 |
|---|---|---|---|
| 灰境行者 | 18 / 4 / 3 / 100 | 均衡，甜根与黑莓 | 默认 |
| 盾誓守卫 | 22 / 4 / 3 / 100 | 守势、精准格挡、塔盾 | 获得 S 评价 |
| 符文术士 | 15 / 3 / 4 / 90 | 火球、符能储备、符文指环 | 击败赤塔领主 |
| 黑木猎手 | 17 / 4 / 3 / 110 | 放血斩、采集者、寻路者 | 累计采集 10 次 |

A 评价另解锁打断系稀有战术；通关另解锁时间系。新旅程重置当前地图进度、等级和构筑，保留永久进度。表中是职业基础属性，装备可进一步提高上限。

### Boss、胜败与重开

三个塔印守卫独立于普通怪，按取得塔印的进度逐级增强；战败不推进，换地点不降低档位。取得三印后的额外精英维持第三档。精英和领主都有缓慢狂暴，具体数值与行为见敌人图鉴和当前意图；已锁定或被延迟的意图保留锁定时的数值。

赤塔领主有三个阶段，在生成新批次时确定该批规则：

- HP 高于 2/3：三步全部公开，攻击与防御交替穿插重击。
- HP 在 1/3 以上至 2/3：更强攻击及吸能，第三个意图隐藏。隐藏标记随意图交换或延迟移动，不能靠换槽或预演揭露。
- HP 不超过 1/3：强攻，轮流封印一个玩家槽位，该槽只能等待。

战胜后回到世界并发放经验与升级选择；Boss 胜利先处理“继续探索”等胜利选择，再处理待发奖励。继续探索保留本局成果。

主动撤退暂时禁用，战斗中不能主动退出。战败后游戏结束，不恢复生命、不清理敌人、不获得胜利奖励。结束页显示死亡原因、职业、等级与当前经验、世界回合、击败数、塔印、到访格数和最终构筑。

点击结束页“重新开始”后选择职业，重置本局旅程、保留永久成长。Agent 控制时由这次点击先接管，新旅程由人工控制，可再次交给 Agent。训练功能已移除；普通旧存档仍可读取，旧训练中存档会明确拒绝。死亡存档读取后仍显示结束页。

导航显示的距离是横纵格数之和的“直线估距”，每五格分档，不包含障碍与绕路成本。多个目标距离分别为 3、4、5 时，都会显示“5 格内”。

## 存档与局外成长

- 当前旅程手动保存到项目目录 `saves/manual.json`；局外成长变化时自动保存到 `saves/meta.json`，打开游戏自动恢复。两者均不使用 localStorage，不兼容旧单 HTML 版存档。
- 局外成长包含通关次数、最佳评价、累计采集与永久职业/战术解锁。页面显示读取、保存和失败重试状态；文件缺失视为首次游玩，损坏或读取失败时暂停进入游戏并提供重试。
- 首次没有 `meta.json` 时，从现有有效 `manual.json` 提取局外成长，不自动加载旅程。读取手动存档时，解锁取并集、评价和累计计数取较大值，不回退已有局外成长。
- 页面提供固定 manual 存档位的保存和读取。没有任意 JSON 导入/导出按钮；需备份时由玩家复制 `saves/` 中的两个文件。普通玩法 agent 不可自行读取或导出完整存档。
- 手动保存包含当前旅程、局外成长、当前战斗/待选决策及玩法随机流；加载先校验候选快照，成功后才替换当前局并使旧身份/命令失效。
- 完整存档包含内部状态，不能把它当公平游戏的 observation。`.gitignore` 排除运行凭据、缓存、日志和构建产物，保留 `saves/` 与依赖锁文件。
- 重要存档自行备份；关闭网页前确认保存操作已成功，不以点击按钮推断落盘成功。
